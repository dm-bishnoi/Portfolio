Case study · 001

RadarDraft

Shipped · In production
2025 · Solo build, ongoing
Problem

Drafting is fragmented.

Tracking teams needed a single surface to capture raw observations, attach context, and route them for review. Existing tools either over-structured the workflow or hid the structure behind freeform notes.

The product had to feel like a focused document editor — but with the rails of a real workflow underneath.

Approach

One canvas, two modes.

Drafting happens in a calm editor. Review happens in a structured panel that surfaces metadata without breaking the reading flow. The two modes are never both open at once — that was an early lesson.

I built small, tested often, and kept the keyboard-first shortcuts the spine of the whole UX.

Architecture

Angular front, Node API, Mongo store.

A modular Angular app talks to a small Node/Express service. MongoDB keeps drafts, reviews, and a lightweight audit log. Nothing exotic — the discipline was in keeping boundaries clear.

Architecture diagram · angular → node → mongo
Angular (standalone components) RxJS state Node · Express MongoDB JWT auth
Interface

Quiet by default.

Three density levels, one persistent status footer, and a command bar for everything else. The brand of the product is restraint — typography, hairline borders, and a single accent color do the talking.

Annotated screen · draft mode
Key features

What it ships with.

Keyboard-first drafting, structured review panels, role-based access, an offline-tolerant editor, and a quiet notification system that doesn't shout.
